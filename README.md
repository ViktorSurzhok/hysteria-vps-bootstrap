# Hysteria VPS Bootstrap

Один установочный скрипт для **Hysteria 2 + nginx + Let's Encrypt** на Debian/Ubuntu с systemd. Поддерживает VPS без IPv6, восстановление прерванной установки nginx и повторные запуски.

## Быстрый старт

A-запись должна указывать на IPv4 VPS. Если IPv6 отсутствует, удалите AAAA-запись. Откройте в firewall провайдера TCP 80/443 и выбранный UDP-порт.

```bash
curl -fsSL https://raw.githubusercontent.com/ViktorSurzhok/hysteria-vps-bootstrap/main/setup-hysteria.sh \
  | sudo bash -s -- \
      --domain my.doneone.pro \
      --email admin@doneone.pro \
      --port 443
```

При первой установке пароль запрашивается через `/dev/tty`. При повторной установке без параметров пароля используется существующий пароль. Для автоматизации:

```bash
sudo bash setup-hysteria.sh \
  --domain my.doneone.pro --email admin@doneone.pro \
  --port 443 --password-file /root/.hysteria.pw
```

Файл пароля должен содержать пароль в первой строке и иметь права `600`. Кавычки, `:`, `#`, Unicode и строки вроде `true` сохраняются без изменения. Не передавайте секрет в командной строке, если доступен файл или интерактивный ввод.

## Что изменилось в 1.1

- IPv6 проверяется по состоянию ядра и реальной возможности создать/bind IPv6-сокет. `listen [::]` генерируется только при доступном IPv6; Hysteria на IPv4-only VPS явно слушает `0.0.0.0`.
- До работы с пакетами создаётся закрытая резервная копия конфигурации. Исправляются IPv6-listen в стандартном nginx-сайте и сайте выбранного домена. Посторонние сайты не переписываются: их ошибки `nginx -t` требуют отдельного исправления.
- На время установки блокируется автоматический запуск nginx из пакетных скриптов. Существующая `policy-rc.d` сохраняется, остальные сервисы используют её прежние правила. Выполняются `dpkg --configure -a` и, при необходимости, `apt-get -f install`. Политика восстанавливается при выходе и при следующем запуске после обрыва.
- UFW по умолчанию остаётся в прежнем состоянии. Неактивный firewall не включается. Для активного добавляются TCP 80/443 и выбранный UDP-порт; остальные правила и политики сохраняются.
- Certbot использует `certonly --webroot`. Действующий HTTPS сохраняется при повторной установке, `--force-renew` действительно передаёт `--force-renewal`. Проверяются имя в сертификате, срок действия и соответствие ключа.
- Конфигурация Hysteria записывается в JSON-представлении YAML, чтобы значения пароля не меняли тип или синтаксис. Реальный Hysteria проверяет кандидат от своего пользователя на временном UDP-порту до замены конфига.
- Новый nginx-конфиг проверяется перед применением. При неудачном старте Hysteria восстанавливаются её предыдущие конфигурация, копии сертификатов, hook и состояние сервиса.
- Итоговая проверка проверяет владельца **точного** UDP-сокета, доступ к ключам и локальный HTTPS с проверкой доверия сертификату и SNI.

## Параметры

| Параметр | Значение |
|---|---|
| `--domain` | Обязательный FQDN; все A-записи должны указывать на этот VPS |
| `--email` | Контактный email для Certbot |
| `--port` | UDP-порт, по умолчанию `8443` |
| `--password-file` | Первая строка файла; предпочтительно для автоматизации |
| `--password` | Пароль в аргументах процесса; менее безопасно |
| `--webroot` | По умолчанию `/var/www/<domain>`; абсолютный путь без пробелов и метасимволов |
| `--site-title` | Подзаголовок новой статусной страницы |
| `--cert-mode copy\|acl` | Доставка сертификата, по умолчанию `copy` |
| `--force-renew` | Принудительный выпуск; учитывайте лимиты Let's Encrypt |
| `--ufw keep\|enable\|skip` | Сохранить состояние / явно включить / не трогать UFW |
| `--ssh-port` | Дополнительный разрешённый SSH-порт, можно повторять |
| `--show-password` | Показать пароль в итоговом выводе; по умолчанию скрыт |
| `--yes` | Совместимость со старой версией; не включает firewall |

### SSH и UFW

Для явного включения UFW:

```bash
sudo bash setup-hysteria.sh --domain my.doneone.pro --email admin@doneone.pro \
  --port 443 --ufw enable --ssh-port 2222
```

Скрипт собирает порты из `SSH_CONNECTION`, `sshd -T`, реальных слушателей sshd и `ssh.socket`. Указанные `--ssh-port` дополняют этот список. Перед включением неактивного UFW точное общее allow-правило SSH удаляется и добавляется в начало: UFW иначе оставляет дубликат после deny. У уже активного UFW SSH-правила не меняются, включая запуск с `--ufw enable`. Если порты определить нельзя, включение прекращается. Никаких `ufw reset`, изменений default policy или предположения, что SSH всегда на 22.

Правила доступа на уровне провайдера, маршрутизация и нестандартные правила в `before.rules` не контролируются скриптом. При `--ufw keep` существующие SSH-ограничения не расширяются.

## Сертификаты и продление

В режиме `copy` сертификат и ключ помещаются в каталог `release.*`, доступный группе `hysteria`, затем атомарно переключается симлинк `current`. Владелец — `root:hysteria`, каталоги `750`, файлы `640`. Предыдущая пара сохраняется для восстановления.

В режиме `acl` выдаются права прохода по всей цепочке `/etc/letsencrypt` и чтения текущих файлов сертификата/ключа. Hook повторно применяет ACL после каждого renewal, поскольку новые файлы и chmod Certbot могут изменить эффективные права. Если ACL при первоначальной настройке не работают, включается copy.

Один hook `/etc/letsencrypt/renewal-hooks/deploy/hysteria-bootstrap.sh` обслуживает только нужный `$RENEWED_LINEAGE`. Он синхронизирует материал, проверяет чтение от пользователя Hysteria, перезагружает активный nginx и перезапускает активную Hysteria. Намеренно остановленные службы не запускаются. Старые copy/ACL hooks этого домена удаляются. Включается `certbot.timer`.

Существующий корректный сертификат с запасом более 30 дней повторно не выпускается. Старые сертификаты с nginx-аутентификатором сохраняют прежний механизм продления; установленный ранее `python3-certbot-nginx` не удаляется. При смене webroot уже существующего webroot-lineage используйте прежний путь либо явно `--force-renew`, чтобы Certbot записал новый путь. Без этого скрипт остановится **до** изменения nginx.

После установки на реальном VPS проверьте внешний ACME-проход:

```bash
sudo certbot renew --dry-run
```

Локальная проверка DNS/HTTPS не доказывает доступность порта 80 для серверов Let's Encrypt. Все AAAA-записи должны принадлежать VPS с работающим IPv6; внешняя IPv6-маршрутизация проверяется отдельно.

## Повторные запуски и границы управления

Скрипт рассчитан на один управляемый `hysteria-server` на VPS. Пароль сохраняется, бинарь Hysteria 2 не обновляется автоматически, существующий `index.html` не переписывается. Конфиг Hysteria и vhost выбранного домена управляются скриптом; ручные дополнительные параметры сохраняются в бэкапе, но не переносятся в новый конфиг. Hysteria 1 и несовместимые service units вызывают явную ошибку.

Повторный одновременный запуск блокируется через `flock`. Смена домена существующей установки 1.1 требует отдельной миграции. Бэкапы лежат в `/root/hysteria-vps-bootstrap-backup-<timestamp>.<random>/`, права каталога `700`. Они могут содержать пароли и старые копии приватных ключей; удаляйте ненужные бэкапы согласно своей политике хранения.

Откат Hysteria восстанавливает её файлы и hook, но не отменяет уже установленные системные пакеты, добавленные firewall-правила или успешно выпущенный сертификат. Ошибка выпуска сертификата оставляет HTTP-сайт для исправления ACME и повторного запуска.

## Проверка и диагностика

```bash
bash -n setup-hysteria.sh tests/integration.sh
shellcheck setup-hysteria.sh tests/integration.sh
python3 -m unittest discover -s tests -v
```

GitHub Actions запускает интеграционный сценарий на Ubuntu 22.04 и 24.04 с включённым и отключённым IPv6. Используются реальные nginx, dpkg, systemd, UFW, Hysteria 2 и клиентское QUIC-подключение. Только публичный DNS/IP и выдача ACME заменены локальными fixtures с тестовым CA. Проверяются прерванная установка nginx, повторный запуск через stdin, сохранение пароля, renewal, copy/ACL, откат при занятом UDP-порте и SSH на 2222. `tests/integration.sh` намеренно разрешён только на одноразовых GitHub-hosted runners — не запускайте его на VPS.

На VPS:

```bash
sudo nginx -t
sudo systemctl status nginx hysteria-server certbot.timer --no-pager
sudo journalctl -u nginx -u hysteria-server -n 50 --no-pager
sudo ss -lunp 'sport = :443'
```

Для клиента: Hysteria 2, домен/IP VPS, выбранный UDP-порт, сохранённый пароль и TLS SNI домена. Маскировка отдаёт файлы статусного сайта напрямую, без циклических редиректов на UDP 443.

Поддержка ориентирована на Debian/Ubuntu с systemd и обычными файловыми правами/ACL. SELinux, контейнеры без systemd, сторонние сетевые ограничения и размещение нескольких Hysteria-инстансов требуют отдельной настройки.
